# Foreman против ручной схемы Docker + Nginx + Samba

| Критерий | Foreman | Ручная схема |
|---|---|---|
| DHCP/DNS/PXE | Единая модель объектов и Smart Proxy | Отдельные конфиги, ручная синхронизация |
| Host lifecycle | Build state, callback, audit trail | Набор несвязанных скриптов |
| Шаблоны ОС | ERB, Host Group, параметры и наследование | Статические файлы/копии |
| Ansible | Роли назначаются Host Group, jobs и отчёты в UI | Отдельный inventory и ручной запуск |
| Масштабирование | Proxy на площадку, API/IaC | Рост числа специальных контейнеров и конфигов |
| Ошибки | Валидация, статусы, централизованные логи | Диагностика между DHCP/TFTP/Nginx/Samba |
| Порог входа | Выше, много сущностей и plugins | Ниже для одного образа/одной сети |
| Ресурсы | Тяжелее: Rails, DB, Proxy | Легче и прозрачнее |

Плюсы Foreman: воспроизводимость, аудит, RBAC, inventory, наследование Host Group, единый lifecycle и интеграция Ansible. Минусы: сложное первоначальное развёртывание, чувствительность к версиям plugins/templates, необходимость резервного копирования БД и более высокая стоимость сопровождения.

Ручной сервер удобен как маленький одноразовый стенд. При нескольких ОС, площадках, группах политик и повторных установках стоимость ручной синхронизации быстро превышает стоимость Foreman.
